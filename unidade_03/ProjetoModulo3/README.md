# Projeto Módulo 3 – Low Code/No Code/Vibecode

## 📌 Desafio Escolhido

Site para encontrar onde assistir jogos de futebol.

---

## 🖥️ Breve explicação do protótipo

O projeto busca resolver uma dificuldade muito comum entre os amantes de futebol: descobrir onde assistir aos jogos. Por conta dos diversos direitos de transmissão entre emissoras e plataformas de streaming, muitas vezes é difícil saber onde determinado jogo será transmitido.

O site faz a leitura em tempo real dos jogos que estão acontecendo no momento e direciona o usuário para a plataforma ou serviço de streaming responsável pela transmissão da partida.

O principal objetivo do projeto é acabar com a perda de tempo procurando jogo por jogo em diferentes plataformas.

## ⚙️ Plataforma Utilizada

* Bolt.new
* Claude.ai
* GitHub Copilot

### Justificativa da escolha

O Bolt.new foi a melhor escolha pensando em uma plataforma low code gratuita, principalmente por entregar uma boa quantidade de tokens diários para realizar alterações no projeto.

O Claude.ai serviu como suporte para indicar comandos para o Bolt.new e também auxiliar na leitura e resolução de erros encontrados durante o desenvolvimento da aplicação.

Já o GitHub Copilot foi utilizado em alguns momentos, porém acabou sendo pouco aproveitado por conta do limite mensal baixo de tokens.

---

## ✅ Vantagens Identificadas

### 1. Facilidade na criação de projetos

Em poucos minutos a plataforma low code conseguiu gerar um site praticamente completo, mesmo apresentando alguns erros iniciais, mas já com uma ótima base para desenvolvimento.

### 2. Rápida resolução de erros e problemas

Com o auxílio de outras plataformas de IA, como o Claude.ai, foi possível localizar exatamente onde estavam os erros e corrigir problemas no código de forma mais rápida.

### 3. Sugestões de melhorias e soluções

O uso conjunto das plataformas ajudou bastante na busca de melhorias para o código, otimizações e sugestões de APIs que poderiam ser utilizadas no projeto.

---

## ⚠️ Limitações Encontradas

### 1. Baixo limite de tokens

Mesmo o Bolt.new oferecendo uma quantidade razoável de tokens diários, em alguns momentos foi necessário parar o desenvolvimento por falta de créditos. O mesmo aconteceu no Claude.ai, porém os tokens retornavam após algumas horas.

### 2. Limite mensal baixo do GitHub Copilot

O baixo limite mensal do GitHub Copilot acabou impedindo a continuidade do uso da ferramenta, principalmente porque o projeto começou a crescer bastante.

### 3. APIs de futebol completas são pagas

Grande parte das APIs que possuem cobertura completa dos campeonatos brasileiros e internacionais exige pagamento para acesso total e requisições ilimitadas.

### 4. Limite diário de requisições nas APIs gratuitas

As APIs gratuitas utilizadas possuíam limite de aproximadamente 100 requisições por dia, o que acabou limitando bastante os testes e atualizações do projeto.

---

## 📚 Reflexão Crítica

Para resolver o problema das requisições limitadas, a alternativa encontrada foi trocar a API utilizada por outra gratuita, mesmo que ela tivesse menos ligas disponíveis. Em compensação, ela permitia até 10 requisições por minuto, o que ajudou a manter o site mais atualizado em tempo real.

Sobre os limites de tokens das plataformas, a única solução era aguardar o reinício diário do Bolt.new ou o retorno dos créditos do Claude.ai após algumas horas. No caso do GitHub Copilot, a única alternativa seria contratar um plano pago, o que não foi possível durante o desenvolvimento do projeto.
